# 3 分钟演示视频脚本

## 演示目标

这支视频要让评委在 3 分钟内记住一件事：

> SenseLoop 是一个以“岐黄问诊助手”为中心的四诊 Agent。它把 Anker 录音笔 / soundcore Work 记录到的夜间声音作为核心“闻诊”入口，再结合舌苔、排便、体检资料和问诊对话，形成个人健康建议、追问和报告。

本次演示主线：

```text
Anker 录音笔记录夜间声音（闻诊主线）
-> 今日页展示睡眠/鼾声摘要
-> 检测页用望闻问切补充舌苔、排便、资料
-> 岐黄问诊助手结合知识库继续追问和解释
-> 报告页沉淀建议、依据和趋势
-> 我的页绑定用户、设备和健康档案
```

MVP 要强调的闭环：

```text
岐黄问诊助手：持续追问、解释和记忆
+ 闻诊主线：睡眠中的鼾声、咳嗽、夜醒、起夜和环境声音
+ 望/问补充：舌苔、排便、饮食、体检资料
+ 中医知识库：解释四诊线索和健康管理边界
-> 形成个人健康 Agent，而不是一次性的健康打分页面
```

## 快速切入策略

开场直接给评委一个硬件场景：

> 昨晚，Anker 录音笔放在床头，记录到多段打鼾、咳嗽和夜醒声音。  
> 普通设备只能留下录音，SenseLoop 想继续往后走一步：把这些夜间声音交给岐黄问诊助手，结合望闻问切和中医知识库，变成今天的饮食、运动、恢复建议和必要追问。

这个开场有三个效果：

- 先让评委看到 Anker 硬件入口。
- 再说明它不是普通录音回放。
- 最后自然引出 App 里的健康助手闭环。

## 0:00-0:18 开场

画面动作：

1. 打开在线 Demo，停在今日页。
2. 让画面露出“昨晚睡眠 / 鼾声 / 咳嗽 / 今日建议”区域。

口播：

> SenseLoop 的入口不是一个泛健康 App，而是 Anker 录音笔。它放在床头，记录夜间打鼾、咳嗽、夜醒和环境声音。  
> 但产品中心不是一张静态报告，而是岐黄问诊助手。我们用望闻问切组织输入，让声音、舌苔、排便和体检资料进入同一个有记忆的健康 Agent。

## 0:18-0:38 今日页

画面动作：

1. 指向今日页的睡眠摘要。
2. 指向今日建议和恢复建议。

口播：

> 今日页是用户早上打开 App 的第一屏。这里把昨晚的声音事件整理成睡眠和恢复摘要，再给出今天怎么吃、怎么动、怎么恢复。  
> 这个 MVP 先把“所有睡眠声音”作为最稳定的硬件输入，包括鼾声、咳嗽、夜醒、起夜和环境噪声。睡眠和鼾声不会被弱化，它们就是 SenseLoop 的核心闻诊入口。

## 0:38-1:05 检测页

画面动作：

1. 点击底部“检测”。
2. 展示舌诊、夜间声音、体检报告、饮食、排便和口气入口。

口播：

> 检测页把更多输入接进来，但仍然围绕一个框架：望闻问切。  
> 闻诊是录音笔带来的夜间声音；望诊是舌苔、饮食图和体检报告；问诊包含症状、排便和生活习惯补充；切诊未来可以接心率、步数和穿戴体征。检测页的价值不是堆功能，而是把四诊线索送进同一个 Agent 工作流。

## 1:05-1:35 舌诊/资料上传

画面动作：

1. 进入舌诊模块，展示上传舌图或已有舌诊结果。
2. 返回检测页，进入健康资料上传。
3. 展示图片/PDF 摘要结果。

口播：

> 这里补充的是录音笔听不到的信息。用户可以上传舌图，也可以上传体检报告图片或 PDF。  
> 后端会把原始文件保存到服务器本地云磁盘，把摘要、结构化线索和当前健康档案关联起来。这样夜间声音、舌图和报告不再是分散数据，而是进入同一个用户健康上下文。

## 1:35-2:05 问诊助手

画面动作：

1. 点击底部“问诊”。
2. 展示上方用户状态卡。
3. 输入：`结合昨晚睡眠和舌诊，今天怎么安排？`
4. 等待回复出现，停留 2 秒即可。

口播：

> 岐黄问诊助手是这个闭环的中枢。它会结合当前健康档案、昨晚声音摘要、舌诊结果、资料摘要和知识库依据，给用户一个更具体的下一步建议。  
> 比如它可以回答：昨晚鼾声偏多，今天运动强度怎么安排；舌苔偏干，饮食和饮水怎么调整；排便变化和睡眠恢复是否需要继续观察；报告里有异常项目，接下来该补充哪些信息。中医知识库负责给出解释依据和风险边界。

## 2:05-2:30 报告页

画面动作：

1. 点击底部“报告”。
2. 展示今日报告、舌诊结果、资料摘要、依据来源或趋势入口。

口播：

> 报告页负责把 Agent 的判断沉淀下来。录音笔记录的夜间声音、用户补充的舌图和资料、问诊助手给出的建议，都会沉淀成报告和趋势。  
> 用户不是每次从零开始问，而是在持续积累自己的健康档案。

## 2:30-2:48 我的页

画面动作：

1. 点击底部“我的”。
2. 展示账号、设备、健康档案。
3. 展示邮箱验证码登录和档案编辑区域。

口播：

> 我的页解决用户和设备绑定。第一版支持游客自动建档，也支持邮箱验证码登录。  
> 换设备后，用同一邮箱可以继续使用同一份健康档案、历史报告和问诊记忆。

## 2:48-3:00 结尾

画面动作：

1. 回到今日页。
2. 保持在线 Demo 链接可见。

口播：

> 当前线上 Demo 已经部署，后端是 FastAPI，数据库是 PostgreSQL + pgvector，文件存储和知识库检索也已经接通。  
> 下一步接入真实 Anker 录音笔数据后，SenseLoop 就可以从一个录音硬件，延展成围绕望闻问切运行的个人健康 Agent。

最后一句：

> 录音笔负责听见身体信号，岐黄问诊助手负责把信号变成可以追问、可以解释、可以执行的健康建议。
