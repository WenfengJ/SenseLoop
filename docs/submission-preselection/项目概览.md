# 项目概览

## 项目名

**anker-SenseLoop 观息**

副标题：

**以 soundcore 夜间声音为闻诊入口的岐黄问诊 Agent**

## 一句话介绍

观息 SenseLoop 是一款围绕 **岐黄问诊助手** 构建的 AI 健康助手。它用中医“望闻问切”组织多模态健康输入：以 soundcore Work 记录的睡眠声音、鼾声、咳嗽、夜醒作为核心“闻诊”入口，再结合舌苔、排便、饮食、体检资料和问诊对话，形成有记忆、可追问、可解释的个人健康 Agent。

## 解决的问题

用户每天都会产生大量身体信号：睡醒疲惫、夜里打鼾咳嗽、口气变重、舌苔变化、排便不顺、吃完腹胀、减脂期间状态波动。问题不是没有数据，而是用户看不懂这些信号之间的关系，也不知道今天应该怎么调整。

SenseLoop 要解决的是：把这些分散信号接入同一个健康档案，由岐黄问诊助手结合中医知识库和个人记忆，持续解释“发生了什么、可能和什么相关、今天应该怎么做、哪些情况需要继续观察”。

## 产品定位升级

旧口径：

```text
夜间声音 -> 身体信号理解 -> 每日健康报告
```

当前 v2 口径：

```text
岐黄问诊助手
  + 望闻问切四诊 Agent 工作流
  + soundcore 睡眠声音闻诊主线
  + 中医知识库/RAG 依据
  -> 个人健康建议、报告、追问和长期记忆
```

这意味着 SenseLoop 不只是一个报告生成工具，而是一个长期陪伴用户整理健康线索的个人健康助手。

## 使用的 Anker 硬件

### 主硬件：soundcore Work 录音豆

用于夜间声音采集，承担最重要的“闻诊”角色：

- 打鼾。
- 咳嗽。
- 呼吸相关声音。
- 翻身。
- 起夜。
- 环境噪声。
- 重点标记。

### 辅助硬件：eufy 摄像头

用于未来非隐私“望诊”观察场景：

- 饮食记录。
- 老人夜间活动。
- 生活状态观察。

不用于自动拍摄厕所、大便等敏感场景。

## 当前 Demo 能演示什么

- 今日页：昨晚睡眠声音、鼾声/咳嗽/夜醒摘要和今日建议。
- 检测页：用望闻问切组织舌苔、睡眠声音、体检资料、饮食和排便。
- 问诊页：岐黄问诊助手结合当前档案、近 7 天记忆、睡眠声音、舌诊/报告摘要和知识库继续追问。
- 报告页：沉淀今日报告、舌诊报告、资料摘要和趋势线索。
- 我的页：邮箱验证码登录、多健康档案、出生年月日/时辰、四诊档案信息。
- 后端：FastAPI + PostgreSQL + pgvector + 本地文件存储，支持 Agent、RAG 和资料上传链路。

## 创新点

### 1. 从报告页面升级为 Agent 工作流

普通健康 App 多是展示指标和报告；SenseLoop 把指标交给岐黄问诊助手，由 Agent 继续追问、解释、记忆和生成建议。

### 2. 把录音豆重新定义为“闻诊”硬件入口

soundcore Work 不只是会议录音设备，也可以成为夜间身体声音采集入口，帮助用户发现打鼾、咳嗽、夜醒、起夜、环境噪声等趋势。睡眠/鼾声不是被弱化的模块，而是 SenseLoop MVP 最核心的闻诊主线。

### 3. 用望闻问切重构健康输入

- 望：舌苔、饮食图、体检报告、非隐私视觉观察。
- 闻：睡眠声音、鼾声、咳嗽、夜醒、起夜、环境噪声、口气反馈。
- 问：岐黄问诊助手、用户画像、症状描述、排便、生活习惯。
- 切：心率、脉搏、血氧、运动等未来穿戴能力。

### 4. 中医知识库和 RAG 让回答有依据

第一版知识库先用开发者筛选的四诊规则、睡眠声音边界、舌诊标签、排便/饮食/口气管理规则和医疗边界说明。后续通过知识库后台、切片、审核和 GraphRAG，让 Agent 回答可以引用依据，而不是凭空生成。

### 5. 有当前落地，也有未来硬件想象

当前用 soundcore Work 跑通核心闭环；未来演进为 SenseLoop Watch / Band / Pendant，形成 Anker 健康穿戴新品类。卧室环境反馈可以作为后续可选探索，不作为当前比赛交付重点。

## 商业化价值

- 年轻女性：减脂状态教练。
- 老年人：家庭健康关怀入口。
- 上班族：熬夜修复计划。
- 学生：营养和作息助手。
- 失眠人群：睡眠趋势和白天恢复建议。

商业模式可包括：

- 健康穿戴硬件销售。
- App 订阅。
- 家庭健康报告。
- 高级 AI 建议。
- 营养/运动/养老服务合作。
