# 24 小时现场开发计划

## 总原则

现场不推翻当前项目，而是在已跑通的闭环上增强真实设备、真实数据和演示完成度。

核心闭环：

```text
soundcore Work 夜间声音
  -> 声音事件标签
  -> 用户画像和身体信号
  -> 健康知识库
  -> 每日行动建议
```

## 第 0-2 小时：环境确认

- 拉取代码。
- 运行启动脚本。
- 确认前端可访问。
- 确认后台健康接口可访问。
- 检查设备和 SDK 资料。
- 确认官方现场可用能力。

## 第 2-6 小时：soundcore Work 接入

优先目标：

- 获取设备状态。
- 获取录音或录音文件。
- 获取重点标记。
- 将设备数据适配到 `SleepAudioEvent`。

Fallback：

- 如果 SDK 不可用，使用真实录音文件上传。
- 如果音频识别来不及，使用人工标注或半自动标注。
- 如果设备连接不稳定，保留 mock adapter。

## 第 6-10 小时：报告链路增强

- 将真实或上传的声音事件接入报告。
- 显示数据来源：mock / upload / soundcore_sdk。
- 优化睡眠页时间线。
- 增加用户可理解的事件解释。

## 第 10-14 小时：上传入口和视觉增强

- 增加音频上传入口。
- 增加图片上传入口。
- 饮食、舌苔先用模拟识别结果。
- eufy 如可用，接入非隐私视觉事件；如不可用，展示 placeholder。

## 第 14-18 小时：AI 文案和建议优化

- 如有 API Key，接入 LLM adapter。
- LLM 只负责润色文案。
- 风险提醒仍由规则引擎控制。
- 无 API Key 时保留本地模板。

## 第 18-21 小时：演示稳定性

- 固定演示数据。
- 准备 3 条演示路径：减脂、老人、上班族。
- 准备设备不可用时的备选流程。
- 检查移动端/桌面端页面显示。

## 第 21-24 小时：路演材料

- 录制备用视频。
- 截图核心页面。
- 更新 README。
- 准备 3 分钟讲稿。
- 准备答辩问题。

## 风险预案

| 风险 | 预案 |
| --- | --- |
| SDK 不可用 | 使用 mock adapter 和上传音频 |
| API Key 不可用 | 使用本地规则引擎 |
| 网络不可用 | 前端和零依赖后台本地运行 |
| 设备连接不稳定 | 使用预录音频和演示数据 |
| 图像识别来不及 | 使用手动标签和模拟识别结果 |
| 时间不够 | 优先保证首页、睡眠页、日报页三页闭环 |
