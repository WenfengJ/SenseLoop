# Roadmap 路线图

## 目标

这份路线图用于说明 SenseLoop 不是一次性 Demo，而是一条从黑客松 MVP 走向真实健康助手产品的路径。

核心方向：

```text
Anker / soundcore 夜间声音入口
  -> 望闻问切多模态输入
  -> 岐黄问诊 Agent
  -> 中医知识库依据
  -> 个人健康建议、报告和记忆
```

当前 MVP 先证明一件事：

> 用户早上打开 App，不只是看到昨晚录了什么声音，而是得到今天怎么吃、怎么动、怎么恢复，以及哪些变化需要继续观察。

## 阶段一：v2 Agent 闭环

### 阶段定位

把当前 Demo 从“多个健康页面”收束成一个可解释的 Agent 产品闭环。

核心产品结构：

```text
今日 -> 检测 -> 问诊 -> 报告 -> 我的
```

四诊输入组织：

- 望：舌苔、饮食图、体检报告图片/PDF。
- 闻：睡眠声音、鼾声、咳嗽、起夜、环境噪声。
- 问：岐黄问诊助手、症状描述、生活习惯、排便反馈。
- 切：心率、步数、运动、未来穿戴体征。

### 当前已完成/正在完成

- FastAPI 后端。
- PostgreSQL + pgvector。
- 游客身份和邮箱验证码登录。
- 多健康档案和 `profileId` 绑定。
- 岐黄问诊助手 API。
- 近 7 天记忆摘要设计。
- 舌诊、资料上传、报告摘要、问诊助手入口。
- 本地磁盘文件存储。
- 占位中医知识库和检索接口。
- 线上 Demo 部署。

### 本阶段验收标准

- 用户能创建/切换档案。
- 睡眠声音、舌苔、排便、资料上传和问诊都绑定当前档案。
- 问诊助手能引用睡眠、舌诊、报告摘要和知识库。
- 报告页能沉淀结果，而不是只展示一次性聊天。

## 阶段二：soundcore 数据接入

### 阶段定位

把“闻诊主线”从 mock 数据推进到真实 soundcore 样例数据。

优先目标：

- 接入 soundcore Work 真实样例或导出的录音文件。
- 将录音片段转换成统一的 `SleepAudioEvent`。
- 标记数据来源：`mock / upload / soundcore_sdk / audio_model`。
- 展示鼾声、咳嗽、夜醒、起夜、环境噪声的时间线。
- 让问诊助手能回答“昨晚为什么醒来累”“鼾声多今天怎么安排”。

Fallback：

- SDK 未开放时，使用真实录音文件上传。
- 音频模型来不及时，使用人工标注的声音事件。
- 设备连接不稳定时，使用固定样例保证演示。

## 阶段三：OCR / 视觉增强

### 阶段定位

补强“望诊”输入，让图片/PDF 真正进入 Agent 上下文。

优先能力：

- 体检报告 PDF 文本提取。
- 图片型报告 OCR。
- 舌图视觉理解。
- 饮食图识别和用户修正。
- 图片/PDF 原始文件和摘要分离保存。

边界：

- 不直接给疾病诊断。
- 对异常指标只做解释、追问和就医提醒。
- 舌诊只说倾向和健康管理建议，不说确诊。

## 阶段四：知识库后台

### 阶段定位

把占位知识库升级成可维护、可审核、可追溯的中医健康知识库。

第一批知识来源：

- 项目内四诊规则。
- 睡眠声音与健康管理边界。
- 舌诊标签解释。
- 排便、口气、饮食、睡眠管理规则。
- 药食同源建议边界。
- 医疗风险和就医提醒规则。
- 用户隐私和医疗边界说明。

后台能力：

- 文档导入。
- 切片。
- 标签管理。
- 版本管理。
- 审核状态。
- 引用来源展示。

## 阶段五：GraphRAG

### 阶段定位

当知识库规模变大后，用 GraphRAG 处理“症状-声音-舌象-饮食-建议-风险边界”之间的关系。

适合解决的问题：

- 打鼾、口干、舌苔偏厚、晚餐油腻之间是否有关联。
- 某个用户连续 7 天睡眠差，应该优先追问哪些信息。
- 某条建议来自哪些知识卡、历史记录和检测结果。
- 如何避免 Agent 只靠单次对话给出片面建议。

阶段目标：

- 构建知识节点和关系。
- 建立用户状态图谱。
- 让报告可以展示依据链路。
- 让问诊助手有更强的追问策略。

## 阶段六：多设备正式账号体系

### 阶段定位

从演示级游客/邮箱验证码，升级为可长期使用的账号体系。

能力范围：

- 邮箱/手机号/微信/Apple 登录。
- 多设备登录。
- 多健康档案管理。
- 家庭成员授权。
- 设备绑定。
- 数据导出和删除。
- 账号注销。

隐私要求：

- Agent 工具调用必须绑定 `profileId`。
- 不允许模型跨用户读取数据。
- 敏感文件和长期摘要分离。
- 用户可以删除原始文件、聊天记录和记忆摘要。

## 阶段七：对象存储迁移

### 阶段定位

当前 MVP 使用服务器本地云磁盘保存图片/PDF，适合比赛演示和低成本验证。生产环境需要迁移到对象存储。

迁移目标：

- 图片、PDF、音频进入对象存储。
- 数据库只保存文件索引、摘要、哈希和权限信息。
- 文件访问使用短期签名 URL。
- 支持生命周期管理。
- 支持冷热分层。
- 支持用户删除和审计。

推荐选型：

- 国内云：阿里云 OSS / 腾讯 COS / 华为 OBS。
- 海外云：AWS S3 / Cloudflare R2。
- 自建兼容：MinIO。

## 总体路线

```text
v2 Agent 闭环
  -> soundcore 数据接入
  -> OCR / 视觉增强
  -> 知识库后台
  -> GraphRAG
  -> 多设备正式账号体系
  -> 对象存储迁移
```

## 一句话总结

SenseLoop 的路线不是先做一个大而全的健康 App，而是先用 soundcore 夜间声音跑通“闻诊”主线，再把舌苔、排便、报告、问诊和知识库接进同一个有记忆的个人健康 Agent。
