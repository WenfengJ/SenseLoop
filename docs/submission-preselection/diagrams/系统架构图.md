```text

  -> 多模态身体信号
  -> 四诊特征抽取与用户记忆
  -> 知识库/RAG 与岐黄问诊助手

  -> 未来健康穿戴产品化
```

## 架构说明

### 1. 数据采集层

- **soundcore Work**：当前主硬件入口，用于夜间声音、重点标记、打鼾、咳嗽、起夜、环境噪声。
- **App 输入**：用户画像、醒后反馈、饮食、排便、舌苔、口气等主动记录。
- **手机拍照 / eufy**：饮食、舌苔、非隐私视觉观察。
- **未来传感器**：心率、血氧、脉搏、口气/VOC 等穿戴能力。

### 2. 信号标签层

把不同来源的数据统一成结构化标签：

- `SleepAudioEvent`
- `DailySignals`
- `UserProfile`
- `HealthDocument`
- `AgentMemory`
- `KnowledgeChunk`

页面和报告生成层不直接依赖某一个 SDK。现场如果拿到 soundcore Work SDK，只需要替换 adapter，不需要推翻整体架构。

### 3. 用户与档案层

当前已形成基础用户体系：

- `user_accounts`：邮箱账号或游客账号。
- `user_devices`：不同设备与账号绑定。
- `account_profiles`：账号下的多个健康档案。
- 所有睡眠、检测、报告、问诊、记忆和资料摘要都以 `profileId` 为隔离边界。

这保证了“不同设备登录同一邮箱继续使用同一档案”，也能支持家庭成员或多个健康档案。

### 4. 四诊 Agent 理解层

核心由三部分组成：

- 四诊特征：望诊图片/报告、闻诊夜间声音、问诊聊天、切诊未来体征。
- 近 7 天记忆：问诊、睡眠、舌诊、健康资料摘要会压缩成 profile 级记忆。
- 知识库/RAG：当前使用项目内四诊规则、夜间声音边界、舌诊饮食边界、隐私边界占位知识卡。
- 岐黄问诊助手：读取 profile、signals、report、memory、knowledge cards 后生成追问和健康管理建议。
- 资料解读：PDF 优先提取文本，图片优先调用视觉模型；无法可靠识别时不猜测结论。

医疗安全边界：

- 不做疾病诊断。
- 不替代医生。
- 对持续不适、明显异常或高风险信号提示咨询医生。
- 使用“倾向 / 可能相关 / 建议观察 / 需要进一步确认”等表达。

### 5. 展示层

当前 Demo 包含：

- 今日：昨晚睡眠/鼾声摘要、今日建议、问诊入口。
- 检测：舌诊、闻诊、饮食、排便、口气、体检报告/图片/PDF 解读。
- 问诊：岐黄问诊助手聊天、文件上传、近 7 天记忆。
- 报告：日报、历史报告、趋势入口。
- 我的：邮箱/游客身份、设备、健康档案新建/编辑、隐私说明。
- 说明：架构与演示叙事。

### 6. 产品化演进

当前使用 soundcore Work 跑通夜间声音闭环；未来可以迁移到：

- SenseLoop Watch。
- SenseLoop Band。
- SenseLoop Pendant。

## 核心表达

SenseLoop 的技术路线不是一次性 Demo，而是：

```text
样例数据和手动记录稳定演示
  -> soundcore adapter 接真实夜间声音
  -> 视觉模型识别舌图/饮食/体检资料
  -> 知识库/RAG 增强解释依据
  -> 多模态四诊 Agent 闭环
  -> 专用健康穿戴硬件
```

## 边界

- 不做医疗诊断。
- 不承诺治疗疾病。
- 不自动拍摄隐私内容。
- 排便、舌苔、口气等敏感数据必须用户主动触发。
- 当前 Demo 优先验证夜间声音到晨间建议的核心闭环。
