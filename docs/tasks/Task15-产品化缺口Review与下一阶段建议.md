# Task 15：SenseLoop v2 需求整理稿

## 1. 核心定位

SenseLoop v2 的核心不是把多个健康功能堆在一起，而是以“岐黄问诊助手”为中心，用中医“望闻问切”组织多模态健康输入的 AI 健康 Agent。

一句话叙事：

> SenseLoop 把“望闻问切”变成 AI Agent 的输入框架，让夜间声音、舌图、问诊对话、体检报告等健康信号进入同一个有记忆、可追问、可解释的中医健康助手。

产品差异化主线：

- 闻诊：soundcore Work 夜间声音、打鼾、咳嗽、起夜、环境噪声。
- 问诊：岐黄问诊助手持续追问、解释、记忆。
- 望诊：舌图、饮食图、体检报告图片/PDF。
- 切诊：心率、步数、运动、未来穿戴体征。

## 2. 产品结构

底部导航确定为：

```text
今日 / 检测 / 问诊 / 报告 / 我的
```

页面职责：

- 今日：今日状态、昨晚睡眠/鼾声摘要、岐黄问诊助手入口、快捷检测入口。
- 检测：四诊检测入口，包括舌诊、闻诊、体检报告、饮食、排便/口气、睡眠声音详情。
- 问诊：岐黄问诊助手聊天窗口，上方保留用户状态卡。
- 报告：历史日报、舌诊报告、体检报告摘要、趋势变化。
- 我的：游客身份、`deviceId / guestUserId / profileId`、档案、设备、隐私设置。

四诊不作为底部 Tab 名称，而是在检测页和助手上下文中解释：

```text
望：舌图、饮食图、体检报告
闻：夜间声音、鼾声、咳嗽、起夜、口气反馈
问：聊天问诊、症状描述、生活习惯
切：心率、步数、运动、未来穿戴体征
```

## 3. 睡眠/鼾声定位

睡眠功能不会被砍掉，反而是 v2 的核心差异化来源。

```text
睡眠/鼾声 = 闻诊主线 + soundcore Work 硬件入口 + 今日建议的重要依据
```

v2 中的呈现：

- 今日页第一屏展示昨晚睡眠摘要、打鼾片段、咳嗽片段、夜醒/起夜、高强度声音事件和今日恢复建议。
- 检测页保留完整“夜间声音详情”：整夜声音地图、事件统计、录音片段、近 7 天打鼾/夜醒趋势和数据来源。
- 问诊助手必须能读取并解释昨晚睡眠/鼾声数据。

边界：

- 只能说“夜间声音趋势观察”。
- 不能诊断睡眠呼吸暂停或具体疾病。
- 连续异常时提示咨询医生。

## 4. 用户体系

第一版采用游客自动建档，不强制正式登录。

需要有：

```text
deviceId
guestUserId
profileId
```

要求：

- 首次进入自动创建游客用户。
- 用户可以创建/切换健康档案。
- 所有检测、报告、问诊、记忆都绑定当前 `profileId`。
- “我的”页面第一版展示 `deviceId / guestUserId / profileId`，方便调试和答辩解释。
- 后续可升级手机号、邮箱、微信、Apple 登录。

## 5. 岐黄问诊助手

名称确定为：

```text
岐黄问诊助手
```

第一版能力：

- 聊天窗口真实可用。
- 绑定当前 `profileId`。
- 上方保留用户状态卡。
- 可读取用户基础档案。
- 可读取近 7 天睡眠、舌诊、报告、问诊摘要。
- 可解释昨晚鼾声/睡眠数据。
- 可解释舌图、体检报告、日报。
- 可根据缺失信息主动追问。
- 可引用占位知识库。
- 可生成中医风格健康管理建议。
- 不称“AI 医生”，不做医疗诊断。

输入支持：

```text
文字 + 图片 + PDF
```

第一版实现策略：

- 文字直接进入问诊上下文。
- 文件上传可在检测页发起，也可在问诊页发起。
- PDF 能提取文本时生成 AI 摘要。
- 图片会优先调用视觉模型通道生成摘要；如果模型不能可靠识别图片内容，则明确提示无法判断，不根据文件名猜测。
- 舌图继续走现有舌诊分析链路。
- 体检报告第一版做“文件上传 + PDF 文本提取 + 图片视觉模型摘要 + 可识别指标结构化”；完整医疗级 OCR 指标归一化仍作为后续增强。

## 6. Agent 记忆

记忆策略：

```text
近 7 天保留较完整上下文，7 天前压缩成摘要记忆。
```

每次问诊后更新记忆。

记忆内容：

- 用户基础档案。
- 健康目标。
- 睡眠/鼾声近 7 天摘要。
- 舌诊结果摘要。
- 体检报告摘要。
- 用户问诊重点。
- AI 给出的关键建议。
- 用户修正或反馈。

隐私原则：

- 长期记忆默认保存摘要，不默认保存原始敏感文件。
- 原始舌图、体检报告、音频属于敏感数据。
- Agent 工具读取数据时必须带 `profileId`。
- 模型不能自己决定读取其他用户数据。

## 7. RAG 与知识库

知识库第一版不做后台上传系统，采用开发者手动导入。

第一批知识库分为两类：

- 产品规则占位卡：使用项目内已有内容整理。
- 真实资料切片：已导入国家卫健委食养指南、药食同源管理规定、中医诊断教学大纲、失眠指南、膳食指南和健康素养资料，共 11 个来源、223 个切片。

产品规则占位卡包括：

- 四诊产品化解释。
- 夜间声音/闻诊边界。
- 舌诊标签解释。
- 睡眠、饮食、排便、口气健康管理规则。
- 药食同源建议边界。
- 医疗风险和就医提醒规则。
- 隐私与医疗边界说明。

RAG 第一版目标：

- Agent 回答时能引用知识卡。
- 报告里能展示“依据来源”。
- 先做简单检索即可，不做 GraphRAG。
- GraphRAG 作为后续高级路线，不进入第一轮实现。

## 8. AI 架构叙事

评委说服主线：

```text
四诊 Agent 工作流
```

推荐架构表达：

```text
四诊输入层
  望：舌图、饮食图、体检报告
  闻：soundcore Work 夜间声音、鼾声、咳嗽、起夜、口气反馈
  问：聊天问诊、症状描述、生活习惯
  切：心率、步数、运动、未来穿戴体征

-> 四诊特征抽取层
-> 近 7 天用户记忆层
-> 知识库/RAG 引用层
-> 岐黄问诊 Agent
-> 今日建议 / 报告 / 趋势 / 追问
```

借鉴 LangGraph 的概念：

- State：用户、档案、消息、检测结果、工具结果。
- Node：睡眠解释、舌诊分析、报告解读、知识检索、风险判断、回复生成。
- Edge：根据输入类型选择流程。
- Thread/checkpoint：支持会话记忆。
- ToolNode：调用数据库、知识库、报告、文件解析等工具。
- Summary memory：控制上下文成本。

## 9. 隐私与安全说辞

隐私第一版不一定全部实现，但必须形成理论设计。

核心说法：

```text
敏感数据分级
原始文件与摘要分离
长期记忆只存摘要
Agent 工具调用绑定 profileId
用户可删除
高风险提示就医
```

医疗边界：

- 不做疾病诊断。
- 不替代医生。
- 不把中医辨证说成医学确诊。
- 使用“倾向 / 建议观察 / 可能相关”。
- 对持续疼痛、出血、发热、明显不适、严重睡眠异常提示就医。

## 10. 第一轮开发优先级

第一优先级：

```text
用户 + 问诊 Agent
```

第一轮实现内容：

1. 游客用户和 `profileId` 绑定。
2. “我的”页展示 `deviceId / guestUserId / profileId`。
3. 底部导航调整为 `今日 / 检测 / 问诊 / 报告 / 我的`。
4. 今日页突出睡眠/鼾声摘要和岐黄问诊助手入口。
5. 问诊页做真实聊天窗口，并保留用户状态卡。
6. Agent 会话绑定 `profileId`。
7. Agent 能读取近 7 天睡眠、报告、舌诊、问诊摘要。
8. 每次问诊后更新 7 天记忆摘要。
9. Agent 必须能解释昨晚鼾声/睡眠数据。
10. 文件上传入口雏形：检测页和问诊页都可进入。
11. 体检报告/图片/PDF 先做上传和 AI 摘要。
12. 项目内四诊规则整理成占位知识库。
13. Agent 回答可引用占位知识卡。
14. 报告页保留历史报告和趋势入口。
