# SenseLoop 本轮修改说明与后续建议

> 更新时间：2026-09-26
> 说明：本轮主要调整前端产品结构与交互，目标是让 Demo 更接近一款成熟的个人健康助手。当前修改已在本地完成，线上地址仍需重新部署后才会同步更新。

## 一、本轮修改了哪些模块

### 1. 用户与家庭档案

原来的“减脂女性、老人关怀、熬夜上班族、学生、失眠人群”被改为“我、父亲、母亲、儿子、伴侣”。用户首先是一个具体的人，减脂、睡眠恢复、长辈关怀等内容改为这个人的健康目标或档案标签，不再把人强行归入互斥的人群类别。

### 2. “我的”页面

账号区域参考成熟 App 的个人中心重新设计：默认只展示头像、账号状态和“登录/注册”入口，点击后再展开邮箱登录表单，避免登录模块长期占据大面积空间。同时增加家庭健康档案卡片，可以在“我、父亲、母亲、儿子、伴侣”之间切换，并查看每个人独立的健康目标、年龄和生活信息。

### 3. “检测”页面

“检测”统一改名为“记录”。这个页面的实际作用是收集健康数据，而不是直接给出检测结论；新名称更容易理解，也能降低产品的医疗诊断感。页面继续承载舌象、夜间声音、饮食和健康报告等数据入口。

### 4. 页面返回逻辑

为望诊、闻诊、饮食记录、报告解读和产品说明等二级页面补充统一的返回按钮。用户进入子页面后可以回到原来的记录页，不再需要依赖底部导航重新寻找入口。

### 5. “问助手”入口

底部原来的“问诊”改为“问助手”，并通过凸起、图标、颜色和尺寸强化为主入口。首页仍保留“问问岐黄助手”的按钮，让用户可以带着夜间声音、健康档案和近期记录直接提问。

### 6. 健康测评与舌象结果

移除了旧流程中自动出现的“用户3968、五运六气已完成、综合评分”等硬编码内容。舌象结果现在只有在用户主动记录后才会出现，并改成简单的“舌象参考卡”，展示本次输入、结构化标签和 AI 观察说明，同时明确提示它不能替代医疗诊断。

### 7. 页面切换体验

主导航切换后会自动回到页面顶部；家庭成员切换时继续停留在“我的”页面，方便连续查看不同成员的档案，不再突然跳回首页。

## 二、具体是怎么修改的

本轮遵循了三个原则：

1. **先明确用户，再展示健康标签**：姓名和家庭关系是一级信息，减脂、睡眠、长辈关怀等是二级健康目标。
2. **按使用频率安排界面**：账号登录属于低频操作，因此默认收起；家庭成员切换和问助手属于高频操作，因此放在明显位置。
3. **避免伪造完整诊断**：只有用户真正提交的数据才显示结果；结果优先描述“记录到了什么”和“还需要结合什么观察”，不直接下疾病或体质结论。

具体实现上：

- 重构了顶部档案名称与“我的”页面的信息层级；
- 将账号头部、登录表单、家庭档案和档案编辑拆成不同层级；
- 统一了“记录”相关文案与二级页面的返回组件；
- 调整底部导航样式，强化“问助手”的中心地位；
- 删除旧舌象报告的硬编码演示内容，改为用户主动触发的轻量结果卡；
- 完成 TypeScript 检查和前端构建，并实际点击验证了档案切换、返回路径和主导航。

## 三、建议下一步继续修改的内容

### P0：优先影响比赛表达和核心价值

#### 1. 进一步聚焦产品主线

目前产品仍同时包含夜间声音、舌象、饮食、排便、体检报告和通用健康问答。建议明确“夜间声音与环境如何影响第二天状态”为主线，其他记录作为辅助证据，否则评委可能仍然觉得产品功能很多，但不知道最擅长解决什么问题。

#### 2. 补上“建议—执行—反馈”闭环

目前 AI 能发现问题并给建议，但不知道用户有没有执行。建议增加“今晚尝试”“换一个建议”“做不到”和第二天的“变好、没变化、变差”反馈，让 Agent 能根据真实结果更新长期记忆。这是 SenseLoop 从普通健康报告升级为 AI Native 产品的关键一步。

#### 3. 让录音豆成为看得见的核心硬件

增加录音豆设备卡片，展示连接状态、采集时间、剩余电量、昨晚记录到的声音事件和重点标记。即使暂时使用模拟数据，也要让评委看清楚录音豆如何降低记录成本，以及没有这块硬件时为什么很难完成同样的体验。

#### 4. 清楚标明数据来源和可信程度

恢复分、趋势和 AI 建议应标明来自真实硬件、用户手动输入、演示数据还是 AI 推断。对于证据不足的情况，应明确显示“仍需继续观察”，避免给用户造成已经确认因果或完成诊断的误解。

### P1：提升产品完整度

#### 5. 重新区分“今日”和“报告”

“今日”只负责告诉用户昨晚发生了什么、今天或今晚最应该做什么；“报告”负责展示完整证据、历史趋势和建议依据。减少两个页面之间的信息重复。

#### 6. 收起非核心健康能力

舌象、排便、饮食和体检报告可以统一放入“更多健康记录”，默认不抢占主界面。只有当 Agent 需要补充证据时，再引导用户完成对应记录。

#### 7. 增加真实隐私控制

除了隐私说明，还应提供暂停录音、删除原始音频、清除某段 Agent 记忆、设置数据保留时间和关闭家庭成员共享等真实操作。

#### 8. 完善家庭成员权限

目前可以切换家庭档案，但还需要明确谁能查看父母或孩子的数据、哪些内容可以共享、成员是否已经同意，以及如何撤销授权。

### P2：进一步提升演示成熟度

#### 9. 统一产品语言

继续减少“望闻问切、岐黄问诊、健康评估、检测、测评”等概念同时出现。建议主界面使用“记录、发现、建议、反馈”等通俗语言，中医框架作为辅助解释，不要成为理解门槛。

#### 10. 完善移动端细节和异常状态

继续检查小屏幕下的底部导航遮挡、长文案换行、空数据、网络失败、文件上传失败和低置信度提示，保证现场演示时主链路稳定。

## 四、建议下一版优先完成的最小闭环

```text
录音豆记录一晚声音
  → AI 找到一个值得验证的环境或行为因素
  → 用户确认今晚只调整一个变量
  → 第二天反馈精神、鼻塞、口干或鼾声变化
  → Agent 对比调整前后结果并更新长期记忆
```

如果下一版只能继续完成一件事情，建议优先做这个闭环，而不是继续增加更多健康模块。
